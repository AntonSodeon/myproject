## 2. Живой сервер Paper 1.21.11 (build 132) с двумя клиентами

Клиенты — боты mineflayer 4.39 (протокол 1.21.11). Сценарии лежат в `tests/server/`.
Последний прогон выполнен со сборкой, включающей механику PTrap (основа шляпы — `carved_pumpkin`).
Полный прогон на чистой базе: сценарий 1 → **перезапуск сервера** → сценарий 2; затем сценарий 3.

**Сценарий 1 — 40 из 40:** выдача ключей из консоли и уведомление; главное меню с 5 разделами; попытки вытащить
предметы меню обычным кликом, Shift, цифрой, Q, двойным кликом — безуспешны; кнопки «посмотреть» и «открыть» —
разные предметы; содержимое кейса с шансами и страницами; два быстрых `/cases open` подряд — второе отклонено;
ключ списан и результат сохранён **до окончания анимации**; клики во время анимации ничего не дают; закрытие окна
во время анимации — итог в чате, награда в коллекции; **два игрока открывают одновременно**, результаты не смешаны;
тройной клик «Открыть ещё» → ровно одно открытие; **выход во время анимации** → результат сохранён, при входе показано
уведомление; надевание поверх алмазного шлема → шлем перенесён в инвентарь, не потерян и не раздвоен; шляпу нельзя
снять кликом/Shift/цифрой/Q/ПКМ шлемом; смерть → шляпа не выпала и восстановилась после возрождения; снятие;
нельзя надеть неполученную шляпу; покупка за жетоны с тройным кликом «Купить» → списано один раз; повторно не
продаётся; коллекция «полученные / все» со страницами.

**Сценарий 2 (после перезапуска сервера) — 24 из 25:** выбранная шляпа восстановлена на голове после перезапуска;
балансы и коллекция сохранились; повторная проверка выхода во время анимации; `reload` добавляет кейс; дубликат
→ компенсация «компенсация редкости × multiplier + bonus» ровно один раз, экран результата с «Уже есть в коллекции»,
жетонами и балансом; режим без анимации; **битый YAML при `reload` отклонён, работает прежняя конфигурация**;
кейс с неизвестной шляпой отключён с понятным сообщением, остальные работают; привязка блока к кейсу, список точек,
ПКМ по блоку открывает меню (не сундук) без списания ключа, игрок не может сломать блок, админ снимает привязку;
ресурс-пак: предложение при входе, отказ → сообщение и кнопка повтора, кейсы заблокированы без списания ключа,
принятие → «загружен», кейсы доступны; история открытий.
Один провал — ошибка самого теста (в нём был зашит ID шляпы, которой у игрока не оказалось). Пункт проверен
отдельно в сценарии 3.

**Сценарий 3 — 4 из 4:** ошибка загрузки пака → сообщение и кнопка повтора; надевание без пака работает;
главное меню предупреждает об отсутствии пака; открытие кейса заблокировано, ключ не списан.

**Консоль:** все админ-команды из консоли; офлайн-игрок по нику и по UUID; неизвестный ник отклоняется;
`take` больше баланса → баланс 0; `simulate basic 2000000` → z=1.24, макс. отклонение 0,017 п.п.;
миграция тестового `plugins/PTrap/players.yml`: предпросмотр (2 игрока, 4 записи, 1 неизвестная), перенос,
повторный перенос добавил 0; резервная копия и отчёты созданы.

В логах сервера за все прогоны нет исключений и ошибок плагина (только ожидаемые предупреждения о намеренно
сломанных конфигурациях и незаданном URL пака).

## 2а. Возвращённая механика PTrap — на настоящих данных PTrap

Сначала на сервере работал **оригинальный PTrap 1.1.19**: бот-админ выдал шляпы `/hat grant Tester1 hat_90`, `hat_200`,
игрок надел их через меню PTrap и наложил книгой Шипы III на `hat_90` в наковальне PTrap; ещё один предмет
`hat_150` (Острота V) PTrap импортировал из инвентаря; в инвентаре оставлен предмет `hat_160` с Прочностью III.
Затем PTrap заменён на QWHatCase.

**Сценарий 4 — 28 из 32, сценарий 5 (серверная проверка) — 6 из 6:**
импорт предмета `hat_160` в коллекцию с Прочностью III и удаление предмета; миграция `players.yml`
(3 шляпы) с переносом Шипов III и Остроты V, базовая Защита IV не дублируется; `/hat` открывает коллекцию;
ПКМ — меню «Наложить чар / Надеть»; на голове `carved_pumpkin` с `custom_model_data` 90, Защитой IV, Шипами III,
+3 брони и +2 прочности (проверено `data get` на сервере); книга с Защитой от огня IV и Подводным дыханием III:
двойной клик — книга списана один раз, чары сохранены, надетая шляпа обновилась; не-книга отклонена;
`/hat menu` — магазин с ценой 75 ₽, «Купить в Telegram» даёт ссылку на @AntonSodeon; `/hat grant` — выбор игрока,
поиск по нику через чат, выдача, удаление одной шляпы, `/hat grant Tester1 hat_300` по старому ID,
«Удалить все» с подтверждением (шляпа снята, игрок уведомлён).
4 «провала» сценария 4 — ограничение бота (mineflayer передаёт чары числовыми ID и не видит их по имени);
эти же пункты проверены на сервере в сценарии 5 — пройдено.

**Регрессия с новой сборкой:** сценарии 1, 2, 3 повторены целиком на чистой базе с обновлённым паком v6.2 —
40/40, 25/25, 4/4.
