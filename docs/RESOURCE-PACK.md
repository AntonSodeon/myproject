**Если вы перепаковываете или объединяете пак — SHA-1 изменится, пересчитайте его** (`sha1sum pack.zip`).

## Как плагин выдаёт пак

`config.yml → resource-pack`:

| Параметр | Значение |
|---|---|
| `mode: PLUGIN` | плагин предлагает пак при входе и по `/hats pack` (стекируется поверх пака сервера, не заменяя его) |
| `mode: SERVER` | пак уже выдаёт `server.properties` или другой плагин — QWHatCase только следит за статусом |
| `mode: NONE` | пак не проверяется |
| `url`, `sha1` | прямая ссылка на zip и его SHA-1 |
| `required` | `true` — клиент, отказавшийся от пака, отключается (ванильное «обязательно») |
| `block-cases-until-loaded` | `true` (по умолчанию) — кейсы не открываются, пока пак не загружен |

Обрабатываются состояния: загружен, отказ, ошибка загрузки (`FAILED_DOWNLOAD`, `INVALID_URL`, `FAILED_RELOAD`, `DISCARDED`).
При отказе/ошибке игрок получает сообщение и кликабельную кнопку повторной загрузки.
Баланс, коллекция, надевание и выдача наград работают и без пака; в меню показывается предупреждение
«Ресурс-пак не загружен».

## Если на сервере уже есть свой пак

Плагин не заменяет его автоматически. Варианты:
1. **Два пака** (`mode: PLUGIN`): пак шляп добавляется вторым (клиенты 1.20.3+ поддерживают несколько паков).
   Конфликт возможен, только если серверный пак тоже переопределяет `assets/minecraft/items/carved_pumpkin.json`.
2. **Объединённый пак** (`mode: SERVER`): скопируйте в пак сервера папку `assets/civilization/` и файл
   `assets/minecraft/items/carved_pumpkin.json`. Если в пакете сервера уже есть свой `carved_pumpkin.json`,
   объедините списки `entries` вручную, следя, чтобы номера `threshold` 90…370 не пересекались.
   Затем запустите `tools/validate_pack.py` на результате.

## Проверка отображения (вручную, нужен клиент)

* `/hats collection` → режим «все» → модели в GUI;
* надеть шляпу → F5 (вид от третьего лица) — модель на голове; от первого лица шляпа не мешает обзору;
* второй клиент рядом — шляпа видна другим игрокам (это обычная экипировка, синхронизируется сервером).
