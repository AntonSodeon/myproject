# Миграция с PTrap и откат

Старые данные **только читаются**: `plugins/PTrap/players.yml` и `config.yml` никогда не изменяются и не удаляются.

## Порядок переноса

1. **Резервная копия вручную** (дополнительно к автоматической):
   скопируйте папку `plugins/PTrap/` и текущий ресурс-пак в безопасное место.
2. Остановите сервер. Уберите `PTrap-1.1.19-1.21.11.jar` из `plugins/` (папку `plugins/PTrap/` **оставьте** — из неё читаются данные).
   Положите `QWHatCase-1.0.0.jar` в `plugins/`. Запустите сервер.
3. **Проверка соответствия ID.** Таблица `hat_N → новый ID → модель` — [hat-mapping.md](hat-mapping.md).
   Каждый старый ID записан в `hats.yml` в поле `legacy-ids`.
4. **Предварительный просмотр без записи:**
   ```
   /hatcases migrate
   ```
   Выводит число игроков, записей шляп, сопоставленных и неизвестных шляп, сколько уже перенесено и сколько
   будет добавлено, а также список проблем. Полный отчёт: `plugins/QWHatCase/migration/preview-<время>.txt`.
5. **Перенос** (в течение 5 минут после предпросмотра):
   ```
   /hatcases migrate confirm
   ```
   Перед записью автоматически создаётся резервная копия в `plugins/QWHatCase/backups/migration-<время>/`:
   вся папка старого плагина и снимок БД `qwhatcase-before.db`. Перенос выполняется одной транзакцией —
   при ошибке ничего не записывается. Отчёт: `plugins/QWHatCase/migration/run-<время>.txt`.
6. **Проверьте коллекции** нескольких игроков: `/hatcases inspect <ник>`.
7. **Проверьте модели**: зайдите с паком, `/hats collection` → режим «все», наденьте несколько шляп,
   посмотрите от первого/третьего лица (F5) и со второго клиента.
8. Старый плагин больше не нужен. Папку `plugins/PTrap/` можно архивировать после проверки.

### Повторный запуск

Безопасен: шляпа, уже имеющаяся в коллекции, повторно не добавляется (`INSERT OR IGNORE`).
Каждый запуск фиксируется в таблице `migration_runs` и в журнале действий.

### Неизвестные шляпы

Записи, ID которых нет в `legacy-ids` каталога, попадают в отчёт и в таблицу `legacy_unknown`
(исходный YAML записи сохраняется полностью). Чтобы перенести их позже — добавьте шляпу в `hats.yml`
с нужным `legacy-ids`, выполните `/hatcases reload` и повторите миграцию.

### Чары

Чары, наложенные игроками в наковальне PTrap, переносятся вместе со шляпами (из сохранённых в `players.yml` предметов).
Базовая Защита IV не записывается как личные чары — её даёт `hat-item` в `config.yml` всем шляпам, как в PTrap.

### Выбранная шляпа и предметы в инвентаре

PTrap не хранил выбранную шляпу — она была предметом в слоте шлема. При входе игрока
(`migration.legacy-items: IMPORT`, как функция импорта в PTrap):
* предметы шляп PTrap (метка `ptrap:hat-id` и предыдущие) из инвентаря и слота шлема добавляются в коллекцию
  вместе с чарами, а сами предметы убираются;
* шляпа со шлема становится выбранной и надевается заново;
* тыквы без метки PTrap не трогаются.

`CONVERT` — убирать только предметы уже имеющихся шляп; `IGNORE` — ничего не трогать.

## Откат

1. Остановите сервер.
2. Удалите `QWHatCase-1.0.0.jar` из `plugins/`, верните `PTrap-1.1.19-1.21.11.jar`.
3. `plugins/PTrap/players.yml` не изменялся — коллекции PTrap остаются как были.
4. Чтобы откатить только базу QWHatCase к состоянию до миграции:
   замените `plugins/QWHatCase/data.db` файлом `backups/migration-<время>/qwhatcase-before.db`
   (и удалите `data.db-wal`, `data.db-shm`).

Косметические предметы QWHatCase снимаются с игроков при выходе и при выключении плагина,
поэтому после удаления плагина у игроков не остаётся служебных предметов.
Шляпы, перенесённые в PTrap-коллекцию (`players.yml`), PTrap покажет как раньше; шляпы, полученные только
в QWHatCase (кейсы, каталог, импорт предметов после миграции), есть только в `data.db`.
