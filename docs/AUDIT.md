# Аудит старого плагина PTrap 1.1.19

Источник: `PTrap-1.1.19-1.21.11.jar` (исходников нет). JAR декомпилирован (Vineflower 1.11.1) — это один класс
`ru.f3ta.f3taHat.F3taHat` (~1200 строк), поэтому вместо режима совместимости через API выполнен **полный перенос**:
после миграции старый плагин не нужен.

## Что делал старый плагин

| Область | Как было в PTrap | Как стало в QWHatCase |
|---|---|---|
| Команды | `/hat` (алиас `/hats`): без аргументов — «Мои шляпы», `menu` — магазин, `grant` — админ-GUI выдачи | `/hats`, `/cases`, `/hatcases` (см. [COMMANDS.md](COMMANDS.md)); `/hat` оставлен алиасом |
| Права | одно: `qwhats.admin` (default op) | раздельные права игрока и админа (`qwhatcase.*`) |
| Конфигурация | `config.yml`: тексты, `catalog.first/last-custom-model-data` (90…370), цена «75 ₽», Telegram, объявление | `config.yml`, `hats.yml`, `cases.yml`, `shop.yml`, `messages.yml` |
| Каталог шляп | не было: шляпа = номер модели, ID `hat_<N>`, имя `Шляпа #N`, описание `Кастомная шляпа` | `hats.yml`: 281 шляпа с постоянным ID, названием, описанием, редкостью, категорией |
| Хранение коллекций | `plugins/PTrap/players.yml`: `<uuid>.hats.<hat_id>` = сериализованный ItemStack, `<uuid>.name` | SQLite `data.db`, привязка к UUID |
| Выбранная шляпа | не хранилась: это просто предмет в слоте шлема в файле игрока | `players.selected_hat`, восстанавливается при входе/перезапуске |
| Отображение | предмет `CARVED_PUMPKIN` с `custom_model_data` в **слоте шлема** | тот же слот шлема, та же модель (см. ниже) |
| Привязка к паку | `assets/minecraft/items/carved_pumpkin.json`, `range_dispatch` по `custom_model_data` | без изменений: `item_model = minecraft:carved_pumpkin` + тот же `custom_model_data` |
| Метка предмета | PDC `ptrap:hat-id` (а также старые `qwhats:hat-id`, `f3tahats:hat`); **любая тыква с CMD тоже считалась шляпой** | PDC `qwhatcase:cosmetic`; похожая модель коллекцию не открывает |
| Игровые преимущества | шляпа давала **Защиту IV, +3 брони, +2 прочности брони**; карвинг-тыква защищала от взгляда эндермена; можно было зачаровывать в «виртуальной наковальне» | шляпа не даёт защиты, атрибутов и чар; базовый предмет `PAPER` (не блок, не маскирует от эндерменов) |
| Смерть | шляпа сохранялась в памяти и надевалась после возрождения | шляпа убирается из дропа и восстанавливается из БД |
| Конфликт с бронёй | если на голове шлем — переносился в инвентарь (при полном инвентаре — отказ) | `hat-display.helmet-occupied: MOVE_TO_INVENTORY` (по умолчанию) или `REFUSE`; проклятие несъёмности — отказ |
| Магазин | ссылка на Telegram, цена 75 ₽ | кейсы + каталог за жетоны; ссылка Telegram — кнопка «Купить ключи» (`external-shop`) |
| Объявление | раз в 35 минут | перенесено (`announcement`) |
| Зависимости | только Paper API 1.21.11 | только Paper API 1.21.11 (SQLite-драйвер входит в Paper) |

## Решения, принятые по итогам аудита

1. **Механизм отображения.** Старый плагин использовал только слот шлема. Других механизмов (пакетная подмена
   экипировки, сущности-пассажиры, ProtocolLib/PacketEvents) не было, поэтому одновременное ношение шлема и шляпы
   **не реализовано** — по ТЗ это допускается только при наличии подходящего механизма. Настоящий шлем никогда
   не удаляется: он переносится в свободный слот или надевание отклоняется с объяснением причины.
2. **Базовый предмет.** `PAPER` с компонентами `item_model = minecraft:carved_pumpkin` и `custom_model_data = N`.
   Клиент берёт модель из того же `items/carved_pumpkin.json`, что и раньше, — внешний вид не меняется. Компонент
   `equippable` (слот HEAD, без `camera_overlay`, нельзя надеть/снять ПКМ, раздатчиком) убирает затемнение
   «тыквенной маски» и не позволяет поставить шляпу блоком.
3. **Преимущества убраны** (требование ТЗ «шляпки не дают защиты»): броня/чары старых предметов не переносятся.
   При входе игрока старые предметы шляп, которые уже есть в его новой коллекции, удаляются
   (`migration.legacy-items: CONVERT`), а шляпа из слота шлема становится выбранной. Предметы шляп,
   которых нет в коллекции, не трогаются (запись в лог).
4. **Названия.** У старого плагина не было индивидуальных названий — только шаблон `Шляпа #N` и описание
   `Кастомная шляпа`. Описание сохранено у всех шляп; названия сделаны по имени модели (на русском) и меняются
   свободно, т. к. коллекции хранятся по ID. Соответствие `hat_N → новый ID → модель` — в [hat-mapping.md](hat-mapping.md).
5. **Совместимость с 1.21.11.** Старый плагин вызывал устаревшие API (`setCustomModelData(int)`, `AsyncPlayerChatEvent`,
   `AttributeModifier(UUID…)`); новый собран без предупреждений об устаревании против `paper-api 1.21.11-R0.1-SNAPSHOT`
   и проверен на сервере Paper 1.21.11 build 132.

## Ресурс-пак `demoraRPuniversal_v6.1.zip`

* `pack.mcmeta`: `pack_format 34`, `min_format 32`, `max_format 999` → 1.21.11 (формат 75) поддерживается. Оверлеи `bettermodel_*` корректны.
* Шляпы: `assets/minecraft/items/carved_pumpkin.json` (`range_dispatch` по `custom_model_data`, 415 записей); шляпы плагина — 90…370.
* Проверка `tools/validate_pack.py`: **281 шляпа, 0 ошибок** (все модели, цепочки parent и текстуры на месте, конфликтов ID нет).
* 4 модели без трансформации `display.head`: `warden_horns`, `warden_horns_shiny`, `giant_warden_head`, `giant_warden_head_shiny`
  (CMD 139, 140, 143, 144). Так было и в старом плагине (тот же предмет и модель), но вид на голове нужно проверить глазами.
* `cmd 187` — модель `item/tools/dragon_skull` (из папки инструментов), но имеет `display.head`; включена как шляпа `dragon_skull`.
* Папка `hoplite/` в корне — вложенный пак со своим `pack.mcmeta`, клиент её **не читает** (не оверлей). Можно удалить,
  чтобы уменьшить размер (~31 МБ); на работу плагина не влияет. Пак плагином не изменялся.
