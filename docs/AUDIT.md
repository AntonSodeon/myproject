# Аудит старого плагина PTrap 1.1.19

Источник: `PTrap-1.1.19-1.21.11.jar` (исходников нет). JAR декомпилирован (Vineflower 1.11.1) — это один класс
`ru.f3ta.f3taHat.F3taHat` (~1200 строк), поэтому вместо режима совместимости через API выполнен **полный перенос**:
после миграции старый плагин не нужен.

## Что делал старый плагин

| Область | Как было в PTrap | Как стало в QWHatCase |
|---|---|---|
| Команды | `/hat` (алиас `/hats`): без аргументов — «Мои шляпы», `menu` — магазин, `grant` — админ-GUI выдачи | сохранены: `/hat` — «Мои шляпки», `/hat menu` — магазин, `/hat grant` — админ-меню, `/hat grant <игрок> <id>`; плюс `/hats`, `/cases`, `/hatcases` |
| Права | одно: `qwhats.admin` (default op) | `qwhats.admin` сохранено (даёт все админ-права) + раздельные `qwhatcase.*` |
| Конфигурация | `config.yml`: тексты, `catalog.first/last-custom-model-data` (90…370), цена «75 ₽», Telegram, объявление | `config.yml`, `hats.yml`, `cases.yml`, `shop.yml`, `messages.yml` |
| Каталог шляп | не было: шляпа = номер модели, ID `hat_<N>`, имя `Шляпа #N`, описание `Кастомная шляпа` | `hats.yml`: 281 шляпа с постоянным ID, названием, описанием, редкостью, категорией |
| Хранение коллекций | `plugins/PTrap/players.yml`: `<uuid>.hats.<hat_id>` = сериализованный ItemStack, `<uuid>.name` | SQLite `data.db`, привязка к UUID |
| Выбранная шляпа | не хранилась: это просто предмет в слоте шлема в файле игрока | `players.selected_hat`, восстанавливается при входе/перезапуске |
| Отображение | предмет `CARVED_PUMPKIN` с `custom_model_data` в **слоте шлема** | то же: `CARVED_PUMPKIN`, слот шлема, та же модель |
| Привязка к паку | `assets/minecraft/items/carved_pumpkin.json`, `range_dispatch` по `custom_model_data` | без изменений: `item_model = minecraft:carved_pumpkin` + тот же `custom_model_data` |
| Метка предмета | PDC `ptrap:hat-id` (а также старые `qwhats:hat-id`, `f3tahats:hat`); **любая тыква с CMD тоже считалась шляпой** | PDC `qwhatcase:cosmetic`; старые метки распознаются; тыква без метки коллекцию не открывает (требование ТЗ, защита от подделки) |
| Игровые преимущества | шляпа давала **Защиту IV, +3 брони, +2 прочности брони**; тыква защищала от взгляда эндермена; чары книгами в «виртуальной наковальне» | **сохранено полностью**: Защита IV, +3 брони, +2 прочности (настраивается в `hat-item`), тыква, чары книгами (ПКМ по шляпе → «Наложить чар»); чары хранятся в коллекции и переносятся миграцией |
| Смерть | шляпа сохранялась в памяти и надевалась после возрождения | шляпа убирается из дропа и восстанавливается из БД |
| Админ-выдача | GUI: выбор игрока (онлайн/офлайн, поиск ника через чат), выдать шляпу, удалить шляпу, удалить все с подтверждением | **сохранено** (`/hat grant`) + команды `/hatcases` |
| Импорт предметов | шляпы-предметы из инвентаря добавлялись в коллекцию | **сохранено** (`migration.legacy-items: IMPORT`): шляпа и её чары попадают в коллекцию, шляпа со шлема становится надетой |
| Конфликт с бронёй | если на голове шлем — переносился в инвентарь (при полном инвентаре — отказ) | `hat-display.helmet-occupied: MOVE_TO_INVENTORY` (по умолчанию) или `REFUSE`; проклятие несъёмности — отказ |
| Магазин | каталог всех шляп, цена 75 ₽, «Купить в Telegram» | **сохранён** (`/hat menu`, кнопка в главном меню, `donate-shop`) + кейсы + каталог за жетоны |
| Объявление | раз в 35 минут | перенесено (`announcement`) |
| Зависимости | только Paper API 1.21.11 | только Paper API 1.21.11 (SQLite-драйвер входит в Paper) |

## Решения, принятые по итогам аудита

1. **Вся механика шляп PTrap сохранена** (по требованию заказчика): основа `CARVED_PUMPKIN`, Защита IV, +3 брони,
   +2 прочности брони, чары книгами, магазин с Telegram, админ-меню выдачи, импорт предметов, объявление,
   сохранение шляпы при смерти, запрет снять шляпу кроме как через `/hat`. Отличия только там, где старое поведение
   было уязвимым: шляпа хранится в базе, а не предметом (её нельзя выбросить, передать или раздвоить),
   тыква без метки PTrap не превращается в шляпу.
2. **Механизм отображения.** Старый плагин использовал только слот шлема, поэтому одновременное ношение шлема и
   шляпы не реализовано (как и в PTrap). Настоящий шлем никогда не удаляется: он переносится в свободный слот
   или надевание отклоняется с объяснением.
3. **Предмет на голове.** `CARVED_PUMPKIN` с `custom_model_data = N` — клиент берёт модель из того же
   `items/carved_pumpkin.json`. Компонент `equippable` запрещает надеть/снять шляпу ПКМ и раздатчиком;
   поставить её блоком или использовать в крафте нельзя. Оверлей тыквы в паке прозрачный — обзор не закрывается.
4. **Названия.** У PTrap не было индивидуальных названий — только `Шляпа #N` и описание `Кастомная шляпа`.
   Описание сохранено; названия сделаны по имени модели и меняются свободно (коллекции хранятся по ID).
   Соответствие `hat_N → новый ID → модель` — [hat-mapping.md](hat-mapping.md); старые ID принимает `/hat grant`.
5. **Совместимость с 1.21.11.** Новый код без устаревших API, проверен на Paper 1.21.11 build 132,
   в том числе с настоящими данными, созданными PTrap 1.1.19 на том же сервере.

## Ресурс-пак `demoraRPuniversal_v6.1.zip`

* `pack.mcmeta`: `pack_format 34`, `min_format 32`, `max_format 999` → 1.21.11 (формат 75) поддерживается. Оверлеи `bettermodel_*` корректны.
* Шляпы: `assets/minecraft/items/carved_pumpkin.json` (`range_dispatch` по `custom_model_data`, 415 записей); шляпы плагина — 90…370.
* Проверка `tools/validate_pack.py`: **281 шляпа, 0 ошибок** (все модели, цепочки parent и текстуры на месте, конфликтов ID нет).
* 4 модели без трансформации `display.head`: `warden_horns`, `warden_horns_shiny`, `giant_warden_head`, `giant_warden_head_shiny`
  (CMD 139, 140, 143, 144). Так было и в старом плагине (тот же предмет и модель), но вид на голове нужно проверить глазами.
* `cmd 187` — модель `item/tools/dragon_skull` (из папки инструментов), но имеет `display.head`; включена как шляпа `dragon_skull`.
* Папка `hoplite/` в корне — вложенный пак, клиент её **не читает**, хотя основной пак ссылается на её файлы
  (звуки кейсов и др.). Исправлено в обновлённом паке v6.2 — см. [PACK-CHANGES.md](PACK-CHANGES.md).
* 4 модели без `display.head` построены в координатах «блока на голове» (как сама тыква) и выводятся так же, как в PTrap.
